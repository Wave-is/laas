# Профили моделей

`config/model_profiles.yaml` хранит независимые профили. По умолчанию настоящих
моделей нет: пользователь выбирает свои файлы или импортирует существующий
llama-swap. Отсутствующие веса автоматически не загружаются.

Для llama.cpp задаются weights_path, context, quant, backend, gpu_layers,
при необходимости mmproj_path/vision, mtp_depth и KV-настройки. CUDA-устройства
передаются по UUID. Tensor split auto рассчитывается из свободной памяти после
выгрузки предыдущей модели. Явные пропорции должны соответствовать числу GPU.

Проверяются min_gpu_count, max_gpu_count, min_total_vram_mib,
min_free_vram_per_gpu_mib, selection policy и строгие требования транспорта.
Это предварительные ограничения, а не точный расчёт KV-кэша. Неизвестная память
не трактуется как свободная. Для CPU: backend cpu, min_gpu_count 0, gpu_layers 0.
Station дополнительно запрещает GPU offload операций, KV-кэша и mmproj;
один лишь gpu_layers=0 у CUDA-сборки llama.cpp не гарантирует отсутствие GPU-вычислений.

Другие provider_type: openai_compatible и ollama с OpenAI-compatible endpoint
(обычно URL заканчивается /v1). Их процессы и выгрузка управляются внешним сервером.
Текущая сборка не хранит API-ключи внешних моделей; публичные API с обязательной
авторизацией не следует считать настроенными из одного URL.

qualified означает успешный короткий smoke: текст, поток, конкурирующие запросы,
JSON tool call и изображение для vision. Флаг не подтверждает максимальный контекст,
длительную нагрузку или качество сложных агентских задач. После изменения весов,
контекста, backend или аппаратной конфигурации проверку нужно повторить.

В реальном прогоне проверены CPU, одна выбранная CUDA GPU и две CUDA GPU.
ROCm/Vulkan/SYCL не проходили аппаратную квалификацию этой сборки.
