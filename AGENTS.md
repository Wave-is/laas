# Local Agent AI Station: инструкции агенту

## Вход в проект

Пользователь явно требует непрерывности работы при смене агента или исчерпании
контекста. Источник состояния — файлы проекта, а не история чата.

Прочитай в этом порядке:

1. `docs/HANDOFF.md` — цель, текущий этап, подтверждённые результаты и следующие шаги.
2. `handoff-local/README.md` и `handoff-local/SNAPSHOT.json`, если доступны, — данный ПК.
3. `docs/ARCHITECTURE.md` — карта исходников и границы компонентов.
4. `docs/VALIDATION.md` — что именно испытано и какие проверки ещё не выполнены.
5. `docs/WORKLOG.md` — последние завершённые этапы.

Проверь ветку, `git status`, незакоммиченные изменения и соответствие EXE его
`dist/BUILD.json`. Не считай текущий Git HEAD версией уже собранного EXE.
При переносе на другой ПК заново обнаружь зависимости и оборудование.

## Обязательный протокол контрольных точек

- Перед многоэтапной задачей обнови в `docs/HANDOFF.md` раздел «Текущая работа»:
  цель, этап, следующий конкретный шаг и критерий завершения.
- Перед длительной или прерываемой операцией сохрани её команду, изменяемые файлы,
  ожидаемый результат и путь к журналу в локальной контрольной точке. Если операция
  меняет системное состояние, укажи способ проверки и возврата.
- После каждого значимого этапа сохраняй файлы и обновляй «Текущую работу».
  Результат с датой, проверкой и оставшейся проблемой добавляй в `docs/WORKLOG.md`.
  Не откладывай запись до конца сессии или предупреждения о нехватке контекста.
- Перед финальным ответом, передачей или сменой большой задачи обнови
  `docs/HANDOFF.md`, при необходимости `docs/VALIDATION.md`, и локальную заметку.
  Запусти `python tools/handoff_snapshot.py` после последней Git-операции.
  Снимок содержит HEAD, рабочие изменения, сведения о сборке и контрольные суммы.
- Незавершённую работу явно помечай как незавершённую: перечисли затронутые файлы,
  ошибки, запущенные процессы и точный следующий шаг. Не маскируй частичную работу
  успешным итогом. Сохраняй рабочие правки; не делай reset/clean ради чистого статуса.
- Логическая контрольная точка может быть отдельным локальным коммитом.
  Не включай чужие изменения и не делай push только ради сохранения состояния.

Снимок не является автоматическим планировщиком и не заменяет смысловую запись
агента. Если инструмент недоступен, запиши те же сведения вручную.

## Правила проекта

- Это универсальная Windows-панель, а не новый coding-agent. Qwen Desktop —
  основной выбор владельца; Hermes, Pi и OpenClaw поддерживаются независимо.
- GPU, модель, агент, frontend, preset и общая служба — разные уровни управления.
  Выбор агента сам по себе не переключает GPU и не заменяет модель.
- Установка отсутствующего агента открывает официальные релизы. CLI и Desktop
  обнаруживаются отдельно. Не подменяй отсутствие компонента фиктивным статусом.
- Поддержка 0/1/N GPU не означает доступность TCC на любом устройстве. Неизвестные
  метрики отображай как неизвестные. Проверку fixtures отличай от физического опыта.
- Останавливай только процессы с проверенным владением; не используй kill по имени.
  Основной GUI работает без администратора. Привилегированный helper имеет узкий API.
- Старый независимый автозапуск LLM удалён по просьбе владельца. Не восстанавливай
  старые задания; запуском LLM занимается Station. Панель не запускает модель сама
  при первом открытии. Автозапуск панели и модели — отдельные настройки.
- Сохраняй конфигурации с резервными копиями и проверкой внешних правок. Секреты,
  пользовательские настройки, логи и локальные документы передачи не публикуются.
- Авторизация конкретного UAC не означает согласия на другие действия: текущий
  статус старой и новой GPU-служб смотри в handoff, затем проверь фактически.

## Проверки

Команды находятся в `docs/HANDOFF.md`, ручной сценарий — в
`docs/TESTING_GUIDE_RU.md`. Выполняй проверки по масштабу изменения.
Для правок только документации достаточно проверить ссылки и согласованность;
не выдавай ранее пройденные тесты за новый прогон.
